## Что нужно заменить при переносе

Все упоминания BRICS / BRICS+ должны быть удалены или переформулированы без привязки к конкретным союзам и странам.

Критичные места:

- DEEP TECH BRICS+
- Операционная система технологического партнёрства BRICS+
- выход на рынки BRICS+
- страны BRICS+
- DEEP TECH BRICS+-решения
- технологические партнёрства и выход на рынки BRICS+
- footer с DEEP TECH BRICS+

## Правило замены

Не делать механическую замену слова BRICS на слово "международный".

Нужно сохранять смысл конкретной фразы.

Примеры:

- "технологического партнёрства BRICS+" -> "международного технологического партнёрства"
- "выход на рынки BRICS+" -> "выход на международные рынки"
- "DEEP TECH BRICS+-решений" -> "международных DEEP TECH решений"
- "15+ стран BRICS+" -> "15+ стран"

## Что переносим без изменения смысла

- структура блоков;
- основные тексты;
- метрики;
- названия модулей;
- CTA;
- контакты;
- существующую форму;
- desktop/mobile логику;
- основные визуальные паттерны.

## Что пока нельзя полностью зафиксировать по публичному HTML

Автоматический доступ к текущему сайту ограничен динамической реализацией страницы, поэтому перед визуальным переносом дополнительно потребуется сверять:

- точные изображения и фоновые assets;
- шрифты;
- размеры и отступы;
- анимации;
- hover-состояния;
- мобильное меню;
- фактические URL у кнопок;
- поведение формы;
- скрытые popup/modal элементы.

Это проверяется в процессе визуального воспроизведения сайта.

## Вывод

Для текущего согласованного этапа сайт не требует сложной архитектуры.

Оптимальный вариант для переноса:
- Next.js;
- TypeScript;
- CSS Modules или обычный CSS;
- статические данные в коде на первом этапе;
- без базы данных;
- без CMS;
- без микросервисов.

Это позволит быстро и точно перенести текущий лендинг, а дополнительные системы не будут мешать текущему scope.
